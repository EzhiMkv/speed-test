# speed-test

[![CI](https://github.com/EzhiMkv/speed-test/actions/workflows/ci.yml/badge.svg)](https://github.com/EzhiMkv/speed-test/actions/workflows/ci.yml)

Консольный скрипт для замера скорости скачивания: делает 10 последовательных
GET-запросов к одному адресу, дожидается полного ответа на каждый и считает
среднюю скорость.

## Требования

- Python 3.10+ (Linux/macOS/Windows).
- Только стандартная библиотека — ничего устанавливать не нужно.

## Запуск

```bash
python3 speed_test.py <URL> [опции]
```

| Опция | По умолчанию | Описание |
|---|---|---|
| `URL` | — | адрес файла для скачивания, например тяжёлая картинка |
| `-n`, `--count` | `10` | количество запросов |
| `--timeout` | `30` | тайм-аут одного запроса, секунд |
| `--no-warmup` | — | не делать прогревочный запрос перед замерами |

Пример:

```bash
python3 speed_test.py "https://proof.ovh.net/files/10Mb.dat"
```

На Windows команда `python` вместо `python3`.

## Единицы измерения

- **Скорость** — Мбит/с, в скобках дублируется МБ/с.
- **Объём** — Б / КБ / МБ / ГБ, десятичные единицы: 1 КБ = 1000 Б, 1 МБ = 10⁶ Б.
- **Скорость** тоже десятичная: 1 Мбит/с = 10⁶ бит/с.

## Как считается

- Время запроса — от старта соединения (DNS, TCP, TLS) до получения
  последнего байта ответа; замер через `time.perf_counter()`.
- Перед замерами идёт один прогревочный запрос — в статистику он не
  попадает (отключается `--no-warmup`).
- Медиана (p50) и p95 считаются по длительностям успешных запросов,
  линейная интерполяция, как в `numpy.percentile`.
- Скорость — общий объём, делённый на сумму длительностей успешных запросов;
  паузы между запросами не учитываются.

## Решения и допущения

- **Только стандартная библиотека.** Замер простой — зависимости и
  `pip install` не нужны, скрипт запускается на любой машине с Python.
- **Запросы строго последовательные** — по условию задачи. Параллельность
  исказила бы результат: запросы делили бы канал между собой.
- **Время запроса включает установку соединения** (DNS, TCP, TLS) — интересует
  полное время «отправил запрос → получил ответ», а не только передача тела.
- **Скорость считается без пауз между запросами** — паузы не относятся к
  пропускной способности канала.
- **Ошибка не прерывает счёт** — один сбой сети не обнуляет остальные
  замеры, итог считается по успешным.
- **Первый запрос — прогрев, а не замер.** Он один платит за установку
  соединения; без прогрева он искажал бы итоговые метрики.
- **Медиана и p95, а не только среднее** — сеть даёт выбросы; p50
  показывает типичный запрос, p95 — «хвост» распределения.
- **Скорость в битах, объём в байтах, приставки десятичные (СИ)** — так
  скорость сети принято указывать в тарифах провайдеров.

## Поведение при ошибках

- Неудачный запрос (сеть, тайм-аут, HTTP 4xx/5xx) выводится в stderr, счёт
  продолжается дальше.
- Если не прошёл ни один запрос — код выхода `1`; при частичных ошибках и
  хотя бы одном успехе — `0`; некорректные аргументы — `2`.

Примечание: некоторые CDN (Cloudflare, Wikimedia) ограничивают частые
повторные скачивания одного и того же файла (HTTP 429). Для тестов удобнее
файлы со специализированных серверов, например
`https://proof.ovh.net/files/10Mb.dat` или `https://proof.ovh.net/files/100Mb.dat`.
